# Семейный VPN-портал

Лёгкий русскоязычный портал для выдачи отдельного VPN-профиля каждому устройству по короткому одноразовому приглашению. Целевой клиент — INCY; российские ресурсы должны обходить зарубежный VPN на самом клиенте (вариант маршрутизации A).

> **Статус:** production-контур реализован, но готовность подтверждается только
> результатами bootstrap/deploy/canary ниже. На реальных устройствах всё равно
> требуется проверить импорт INCY и RU/direct-маршрутизацию.

Основной provider — `vless-reality`: отдельный UUID создаётся root-owned helper
для каждого устройства, а портал выдаёт часовую непрозрачную subscription-ссылку.
В SQLite хранится только HMAC этой ссылки и opaque provider reference. Режим
`noop` сохранён исключительно для локальных тестов. Telegram long polling и
deny-by-default allowlist входят в тот же Go-процесс.

## Подтверждённые факты о сервере

Read-only аудит от 22 октября 2026 года подтвердил:

- Ubuntu 24.04 LTS, `x86_64`, systemd;
- 1 vCPU и 3,8 GiB RAM (около 3,3 GiB было доступно во время аудита);
- корневой диск 48 GiB: 14 GiB занято, 35 GiB свободно;
- Docker установлен и запущен;
- существующий контейнер `amnezia-awg2` работает и публикует UDP `35473`;
- до bootstrap UFW был неактивен, присутствовали таблицы nftables Docker/Tailscale;
- публичные TCP 80/443 во время аудита не были заняты;
- DNS `vpn.akalmaz.tech` указывает на сервер;
- IP-диапазон зарегистрирован у Hostinger в Литве, поэтому российский direct-трафик нельзя реализовать повторным выходом через этот сервер.

Существующая Amnezia не должна останавливаться или удаляться до отдельного canary-развёртывания, проверки клиентов и проверенного rollback.

## Поток пользователя

1. Администратор создаёт приглашение через закрытый интерфейс или Telegram-бота.
2. Родственник вводит короткий код на `https://vpn.akalmaz.tech`.
3. Сервер атомарно погашает приглашение и создаёт отдельные credentials для одного устройства.
4. Портал предлагает установку INCY, import/deep link и резервную загрузку подписки.
5. Каждое устройство можно отозвать независимо.

Код не должен попадать в URL или access logs. ОС может потребовать ручное подтверждение установки VPN-профиля.

## Разработка

Ожидается Go toolchain из `go.mod`. Обязательные локальные проверки:

```bash
go test -race -count=1 ./...
go vet ./...
go build ./cmd/...
```

Секреты нельзя помещать в `.env`, репозиторий, артефакты или логи. Для GitHub Actions предусмотрены имена:

- `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER`;
- `DEPLOY_SSH_PRIVATE_KEY`, `DEPLOY_SSH_KNOWN_HOSTS`;
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_IDS`.

Один ключ/UUID должен соответствовать ровно одному устройству. Отсутствие бизнес-лимита на количество устройств не отменяет технических пределов сервера и защиты от массовой выдачи.

## Условия готовности

Production можно считать готовым только после успешных build/test/security checks,
HTTPS health check, одноразовой активации, отзыва одного устройства, проверки
direct/proxy и DNS-маршрутизации на реальных клиентах, рестарта сервисов,
восстановления backup и контролируемого rollback. Автоматический canary проверяет
портал, Reality egress, activation/subscription/revoke и инвалидирование ссылки;
он не заменяет физические Android/iOS/Windows/macOS тесты.
