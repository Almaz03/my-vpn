# Архитектура

Управляющий узел в Литве (`vpn.akalmaz.tech`) хранит SQLite, обслуживает сайт и Telegram-бота. Go-приложение управляет приглашениями, запросами доступа и подписками Hiddify. Ссылка `/s/{token}` хранится только как HMAC и немедленно инвалидируется при отзыве устройства.

VPN data plane работает на Xray VLESS Vision + Reality TCP/443 одновременно в Литве и Финляндии. Каждое устройство получает один UUID на обоих узлах. Полный клиентский JSON содержит два outbound, observatory и `leastPing` balancer. Выдача считается успешной только после добавления UUID на оба edge; частичный результат откатывается. Отзыв идемпотентно удаляет UUID с обоих узлов.

## Масштабируемая схема

Удалённый edge не запускает приложение, Telegram polling или отдельную базу: на нём работают только Xray Reality, локальная Caddy-маскировка и ограниченный helper синхронизации пользователей. Control plane обращается к нему по отдельному deploy-логину с pinned host key; публичного management API нет.

Каждый edge получает отдельный GitHub Environment (`production-edge-2`, `production-edge-3`, …). IP, порт, пользователь, DNS-имя и закреплённый SHA256 fingerprint передаются workflow как публичные параметры; общий repository secret `DEPLOY_SSH_PRIVATE_KEY` используется повторно. Workflow `Bootstrap VPN edge` можно запускать повторно без ротации уже созданных Reality-ключей.

Root-only `/etc/my-vpn/edges.json` задаёт ровно два узла в стабильном порядке LT, FI. Клиентские реквизиты формируются только по запросу валидной подписки и не попадают в SQLite, Telegram или логи.
