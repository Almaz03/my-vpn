# Эксплуатация

## Ежедневные проверки

- состояние systemd-сервиса портала и Caddy;
- локальный и внешний health check;
- срок TLS-сертификата и результат последнего обновления;
- свободные RAM, swap и диск;
- размер SQLite, WAL и каталогов backup;
- частота отказов активации и срабатываний rate limit;
- состояние `amnezia-awg2`, не выводя клиентские ключи;
- результат последнего CI/CD и версию активного релиза.

Health endpoint не должен возвращать конфигурацию, версии зависимостей, список устройств или секреты. Метрики доступны только через loopback либо отдельный административный канал.

## Логи и аудит

В журнале допустимы timestamp, тип события, обезличенный идентификатор устройства/администратора и результат. Запрещены:

- одноразовые коды и параметры запроса с ними;
- Telegram token;
- private keys, полная VPN-конфигурация и deep link;
- содержимое GitHub Secrets;
- необработанные персональные данные.

Access logger должен удалять или не записывать тело запроса. Для systemd journal и Caddy задаются ограничения размера/retention. Повторяющиеся ошибки входа агрегируются, чтобы не создавать канал спама.

## Backup

Минимальный backup включает согласованный snapshot SQLite, server-side конфигурацию без копирования ключей в GitHub и манифест активного релиза. Шифрование, срок хранения и отдельное место хранения определяются до production. Backup без проверенного восстановления не считается рабочим.

Рекомендуемый цикл:

- ежедневный локальный backup с коротким retention;
- периодическая зашифрованная копия вне сервера;
- ежемесячный тест восстановления в изолированный каталог;
- backup перед каждой миграцией/деплоем.

## Инциденты

При подозрении на утечку Telegram token его отзывают в BotFather и заменяют в GitHub/server-side secret store. При утечке credentials одного устройства отзывается только это устройство. При утечке deploy key удаляется соответствующая строка `authorized_keys`, выпускается отдельный новый ключ, обновляется secret и host audit повторяется.

При аномальном переборе временно блокируются активации, сохраняются обезличенные audit events и анализируются источники. Не следует отключать SSH или менять firewall без независимой активной сессии и плана отката.

## Обновления

Обновлять зависимости и ОС небольшими партиями. Перед перезапуском ядра проверить окно работ, backup и доступ к консоли провайдера. Обновление Amnezia выполняется отдельно от портала: их rollback-контуры не смешиваются.

## Текущие риски

- UFW на момент аудита был неактивен;
- фактические nftables-правила и экспозиция IPv6 требуют отдельной проверки;
- ресурсные и сетевые нагрузочные тесты ещё не выполнены;
- совместимость текущего `amnezia-awg2` с автоматическим безопасным provisioning ещё не подтверждена;
- TLS, портал и Telegram-бот ещё не проверены в production.
